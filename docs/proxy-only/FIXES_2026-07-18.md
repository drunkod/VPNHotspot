# Proxy-only production fixes — 2026-07-18

Executable source: `51105e1f785c6b20195fe7d65e91c189dae7bb42`

This follow-up closes the production gaps found after the Track G and Track L code review.

## Daemon transport death now fails closed

`DaemonController` publishes a monotonic unexpected-transport-closure epoch whenever an established daemon transport closes while a lease is still active. Intentional final-lease shutdown does not publish this signal.

`ProxyOnlyService` collects that signal for the lifetime of its daemon lease and immediately:

1. invalidates `ProxyDaemonComposition` health and its current transport epoch;
2. emergency-closes the current backend listener so stale client policy is no longer reachable;
3. bootstraps a replacement daemon transport;
4. requires a fresh acknowledgement identity and deny-first sanitation before exact admission can resume.

The regression triggers the same transport-closure signal used by `DaemonController`; it does not manually call `transportDisconnected()`.

## TCP CONNECT no longer writes a second SOCKS reply

CONNECT setup and relay lifetime are now separate phases. Address resolution, VPN binding, and outbound connect failures are mapped to a SOCKS error only before `REPLY_SUCCEEDED` is sent. An `IOException` during the established relay only closes the streams and cannot inject another SOCKS reply into application data.

A deterministic JVM regression proves that a relay reset after success emits no second protocol reply.

## Additional corrections

- Temporary username/password byte arrays are zeroed after authentication comparison.
- Random credential-generation byte arrays are zeroed after Base64 encoding.
- DV-01 now states that the listener may bind while probes run, but deny-first firewall containment must keep it unreachable until every required probe succeeds and the exact allow transition is acknowledged.

## Remaining evidence boundary

The code-level daemon recovery and SOCKS relay regressions pass. Formal release approval still requires the rooted-device DV-01 through DV-12 evidence, including a real `vpnhotspotd` kill/restart, tether/VPN/uplink packet capture, DNS-blackhole recovery measurements, lifecycle resource baselines, and UI/notification QA.
